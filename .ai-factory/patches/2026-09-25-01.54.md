# Небезопасный default structured output для DeepSeek Chat Completions

**Date:** 2026-09-25 01:54
**Files:** `src/andromeda_ingestion/infrastructure/config.py`, `src/andromeda_ingestion/infrastructure/ai/http_json.py`, `.env.example`, `README.md`, `docs/extraction.md`, `tests/unit/test_ai_contract.py`
**Severity:** medium

## Problem

Адаптер по умолчанию отправлял `response_format.type=json_schema` вместе со схемой, построенной из Pydantic-модели с динамическими полями. Для Chat Completions-провайдеров, включая DeepSeek, безопасный и документированный режим — `json_object`. Из-за этого реальный запрос мог быть отклонён провайдером ещё до извлечения.

## Root Cause

Один default был выбран без привязки к возможностям конкретного API-режима. При этом локальная валидация `LLMExtractionPayload.model_validate(...)` уже являлась правильной границей проверки результата.

## Solution

- Default в настройках и HTTP-адаптере изменён на `json_object`.
- `json_schema` сохранён как явный opt-in для провайдеров и API-режимов со строгой поддержкой JSON Schema.
- Добавлена регрессионная проверка фактического `response_format`.
- Документация и `.env.example` синхронизированы.
- Локальная Pydantic-валидация оставлена общей для обоих режимов.

## Prevention

- Выбирать structured-output режим по возможностям provider/API, а не только по наличию Pydantic-схемы.
- Тестировать payload, который реально отправляется адаптером, включая default-конфигурацию.
- Не удалять локальную валидацию после перехода на JSON mode.
- Для production-подключения отдельно проверять совместимость выбранного режима с конкретным endpoint.
